# StudyRAG 面试说明

## 1. 项目一句话介绍

这个项目是一个面向课程资料的 RAG 学习助手，基础流程是 PDF 解析、文本切块、Embedding 向量化、FAISS 检索和大模型回答。我重点补了检索溯源、低置信度拒答和问答日志导出，让它不只是一个普通文档问答 Demo，而是能支撑后续 RAG 效果分析的应用原型。

## 2. 面试时的讲法

我没有把这个项目做成很复杂的大系统，而是围绕真实 RAG 项目最关键的几个问题做增强：第一是回答可溯源，每次回答都能看到命中的 chunk、相似度 score 和参考片段；第二是低置信度拒答，当检索不到足够相关内容时不强行回答，降低幻觉；第三是问答日志导出，后续可以接入 SearchInsight 分析 Bad Case，形成 RAG 应用和质量诊断闭环。

## 3. 高频问答

**Q1：RAG 的流程是什么？**

A：先解析文档并切成 chunk，再生成 embedding 存入 FAISS。用户提问时检索相关 chunk，把检索结果作为上下文交给大模型回答。

**Q2：为什么要做 chunk 切分？**

A：长文档无法全部放进 prompt，切块后可以只检索和使用相关片段，同时控制 token 成本。

**Q3：Embedding 是什么？**

A：Embedding 是文本的向量表示，用来衡量文本之间的语义相似度。

**Q4：FAISS 在项目里做什么？**

A：FAISS 负责向量相似度检索，根据用户问题找到最相关的课程资料片段。

**Q5：top_k 是什么？**

A：top_k 表示每次检索返回最相关的前 k 个 chunk，k 越大上下文越多，但噪声和 token 成本也可能增加。

**Q6：为什么要展示参考片段和 score？**

A：参考片段和 score 能说明答案依据来自哪里，也方便判断检索是否命中真正相关内容。

**Q7：为什么要做低置信度拒答？**

A：当最高相似度低于阈值时，说明资料依据可能不足。此时拒答可以降低模型幻觉风险。

**Q8：如何评估 RAG 效果？**

A：可以看检索片段是否相关、答案是否忠实于证据、拒答是否合理、用户反馈是否满意，以及 bad case 主要来自检索还是生成。

**Q9：这个项目怎么和 SearchInsight 配合？**

A：StudyRAG 产生日志，SearchInsight 分析日志中的检索为空、答非所问、用户不满意等问题，再反向指导资料补充、prompt 和阈值优化。

**Q10：这个项目还有什么不足？**

A：目前没有页码级 metadata、BM25/Hybrid Search、rerank 和系统化评估集，后续可以在不破坏现有结构的基础上逐步补充。
